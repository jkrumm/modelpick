# modelpick — RALPH Learning Notes

Appended by each group as it completes.

## Group 1: Scaffold & foundation

### What was implemented
- TanStack Start (SSR) app with Bun, `@tanstack/react-start@1.168.11` + `nitro@3.0.260311-beta`
- Mantine v9.2.1 provider + AppShell with top nav (Decider / TTS / STT)
- Three stub routes: `/` (Decider), `/tts`, `/stt` using `createFileRoute`
- `tsr generate` wired into the `typecheck` script to solve the bootstrap chicken-and-egg
- Vitest 3 configured with a separate `vitest.config.ts` (node environment, keeps SSR plugins out)
- Docker Compose postgres on port 5433 with healthcheck
- Makefile wrapping docker compose and bun commands
- Build outputs to `.output/` via Nitro (client + SSR + server bundles)

### Deviations from prompt
- Added `@tanstack/router-cli` to devDependencies — needed for `tsr generate` in typecheck
- `typecheck` script is `tsr generate && tsc --noEmit` (not bare `tsc --noEmit`) because TanStack Router
  requires a generated `routeTree.gen.ts` (with the `FileRoutesByPath` module augmentation) before
  TypeScript can validate `createFileRoute` call sites. Without it, `keyof FileRoutesByPath` resolves
  to `never` and every `createFileRoute` call errors with "not assignable to undefined".
- Used alias `~` in `vite.config.ts` instead of the `resolve.tsconfigPaths` option from the example
  (kept it simple — path aliases not used in the scaffold anyway)

### Gotchas & surprises
- **Bootstrap chicken-and-egg**: `routeTree.gen.ts` is auto-generated by the Vite plugin. Without it,
  `createFileRoute('/')` fails TypeScript with a confusing "not assignable to parameter of type
  'undefined'" error. The fix is `tsr generate` (from `@tanstack/router-cli`) as a pre-typecheck step.
- **`@ts-nocheck` in routeTree.gen.ts is not sufficient**: The file uses `declare module` augmentation
  which provides the `FileRoutesByPath` entries that `createFileRoute` needs. Without the proper module
  augmentation, all route paths become invalid.
- **Mantine CSS in SSR**: importing `@mantine/core/styles.css` directly in `__root.tsx` works — Vite
  extracts it into the client bundle and `HeadContent` injects it as a `<link>` tag.
- **Nitro build outputs to `.output/`** (not `dist/`). `.gitignore` needs this path — it's already
  excluded by default via `.output` entry.

### Security notes
- No secrets in tracked files; all env vars read from `.env` (gitignored)
- Admin gate deferred to later groups as specified

### Tests added
- `src/__tests__/utils.test.ts`: `clamp` and `normalizeScore` utility tests — both will be used by the
  scoring engine in Group 6

### Future improvements
- `ColorSchemeScript` in `<head>` prevents theme flash on page load (already wired)
- Nav uses basic `Button + Link` pattern; Group 8 can upgrade to Mantine Tabs or SegmentedControl

## Group 2: Strictness baseline

### What was implemented
- `tsconfig.json`: added `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`,
  `noFallthroughCasesInSwitch` (all flags from the prompt; `strict: true` + `forceConsistentCasingInFileNames`
  were already present from Group 1)
- Linter: `oxlint@^1.60.0` matching Argo stack — `bun run lint` now runs `oxlint .`
- Formatter: `oxfmt@^0.45.0` matching Argo stack — `bun run format` and `bun run format:check`
- `.oxlintrc.json`: adapted from Argo's config — same plugins (react, typescript, import, unicorn, etc.),
  correctness=error / suspicious=warn categories, `import/no-unassigned-import: off`
- Pre-wired `no-restricted-imports` for `src/charts/**` banning `@visx/tooltip` direct imports per
  `visx-charts.md` (anticipates Group 7)
- Applied `oxfmt` to all source files — reformatted 7 files

### Deviations from prompt
- `verbatimModuleSyntax` not added — not in the requested flags list and would require converting
  `import * as React from 'react'` to `import type`, adding churn before meaningful code exists
- `noPropertyAccessFromIndexSignature` not added — not in the requested list (Argo has it but prompt
  didn't ask for it)
- Lefthook skipped — RALPH instructions say skip if risky; runner already validates on every group
- No separate oxfmt config file (`oxfmt.toml`) — defaults are fine; Argo also runs without one

### Gotchas & surprises
- The existing Group 1 code passed all new strict flags without any changes — the scaffold was already
  clean enough. No cascade to fix.
- `import/no-unassigned-import` fires on `import '@mantine/core/styles.css'` (side-effect import).
  Rule turned off in `.oxlintrc.json` — this is intentional CSS-loading pattern. Argo also disables it.
- `oxfmt` reformatted all 7 source files (spacing, trailing commas, quotes) — zero semantic changes.
- `oxfmt` outputs "No config found, using defaults" as an informational note; exit 0. Argo also has no
  explicit oxfmt config and this is benign.

### Security notes
- No secrets touched

### Tests added
- No new tests — existing 5 tests pass under the new strictness flags

### Future improvements
- Add `verbatimModuleSyntax: true` to tsconfig when it won't cascade into multiple files
- Wire `lefthook` pre-commit hook once the RALPH loop is complete (developer QoL, not loop safety)
